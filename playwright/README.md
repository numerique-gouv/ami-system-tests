

La stack playwright ne gère pas les app mobiles nativement.
Il existe plusieurs solutions pour ajouter cette capacité.
La plus sobre semble être Appwright qui est un client Appium pour plawright, mais d'autres existent.
Les alternatives pour tester des apps mobiles natives avec Playwright:

| # | Approche | En bref                        | Évaluation                                                                                                                                                       | Description                                                                                                                                                                                                                                                                                                                                          |
|---|----------|--------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1 | [**Playwright Android API**](https://playwright.dev/docs/api/class-android) | natif Playwright, expérimental | ❌ WebViews Android uniquement — pas de support iOS, pas d'éléments natifs.                                                                                       | Playwright a une classe [android](https://playwright.dev/docs/api/class-android) qui se connecte en CDP aux WebViews Android. Pas de support natif iOS, et ça ne couvre que les WebViews — pas les éléments natifs SwiftUI/Jetpack Compose.                                                                                                          |
| 2 | [**Appwright**](https://github.com/empirical-run/appwright) (empirical.run) | le plus ancien                 | ⚠️ Projet gelé depuis le 16/12/2024 — des PR de mise à jour des dépendances ouvertes en 2025 sont encore en attente.                                             | C'est une librairie open-source qui colle `@playwright/test` à Appium. On écrit les tests avec l'API Playwright (`device.getByRole(…).tap()`), et Appium pilote les apps natives en dessous. Supporte iOS + Android, émulateurs + vrais devices. C'est la solution la plus documentée pour faire du "Playwright style" sur mobile natif aujourd'hui. |
| 3 | [**Mobilewright**](https://github.com/mobile-next/mobilewright) (mobile-next) | le plus récent (mai 2025)      | 🔬 projet livrant plusieurs release par semaine, trop récent (1er commit le 03/2026) et actif pour être considéré stable, même si prometteur à l'avenir.         | Un framework qui s'inspire de Playwright mais sans Appium — il utilise ses propres drivers natifs iOS/Android. API très proche de Playwright (`screen.getByRole('button').tap()`). Open-source, IA-friendly. Très jeune, écosystème limité pour l'instant.                                                                                           |
| 4 | [**`@playwright/test` + webdriverio en dessous**](https://webdriver.io/docs/frameworks) | l'hybride                      | ➖ Si on utilise webdriverio, les fonctions de bases de playwright sont déjà là. L'ajouter permet d'avoir le même runner et même rapports que d'autres projets... | Utiliser Playwright uniquement comme test runner (assertions, fixtures, reporters) et WebdriverIO + Appium pour piloter l'app. Moins élégant, deux couches distinctes.                                                                                                                                                                               |
